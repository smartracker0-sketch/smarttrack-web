## API additions

- `GET /api/v1/platform/support-contacts`: authenticated reads of the configured channels.
- `GET /api/v1/admin/platform/settings/support-contacts`: root-admin read.
- `PUT /api/v1/admin/platform/settings/support-contacts`: root-admin replacement of all five fields (`email`, `phone`, `whatsapp`, `hours`, `helpUrl`). Empty strings clear channels. The browser's `PATCH /api/admin/platform/support-contacts` proxy requires all five fields and forwards a PUT.
- `GET /api/v1/dashboard/mileage?from=...&to=...&organisationId=...`: at most 31 days; only accessible vehicles; optional tenant IDs narrow permissions. Distance sums positive recorded odometer deltas within the selected period, ignores negative reset deltas, and returns unavailable distance when fewer than two valid samples exist. Trip counts use trips starting within the same period.
- Existing device collection accepts `search` (name, plate, IMEI) and repeated `organisationId` parameters while preserving owner, assignment and organisation restrictions.

Backend migration `V30__platform_settings.sql` must be applied through the normal deployment process before saving Support contacts. No database migration or production deployment has been run for this work.

## Remaining implementation

All 62 design routes are registered. Maintenance Reports scheduling and Reports Automated delivery now use persisted scheduling APIs rather than an unavailable state or passive reminder records.

Report schedules support eleven connected report variants (Maintenance limits its selector to its two reports), once/daily/weekly/monthly recurrence, IANA time zones, rolling 1–31-day periods, CSV/Excel, pause/edit/remove, manual Run now and paged execution history with downloads. The background queue catches up once after downtime and advances to the next future occurrence. Monthly recurrence preserves its original day across short months. Invalid DST-gap start times are rejected. Runs retain their original configuration and generated file; later schedule edits cannot change historical downloads. Owner permissions and session/account state are checked before work and delivery. Concurrent/manual retries use idempotency keys and worker leases. Removing a schedule stops future/queued runs and retains historical files. Earlier passive report records require explicit setup before conversion. Email is offered only with a configured provider; local preview uses in-app delivery. Files are limited to 100,000 rows and 10 MB. V32 is a source migration only; production PostgreSQL migration and actual provider delivery remain unverified.

Root fleet reads now agree across device inventory/search/detail, live objects, alerts, telemetry, mileage and replay. Tenant filters narrow root search, and ordinary users retain owner/assignment/organisation restrictions. Telemetry history now applies its requested date interval and a strict 31-day limit.

Realtime connections now authenticate with a separate 60-second connection ticket obtained through the existing client/admin session. Tickets cannot authenticate REST calls. Server filters subscriptions and every outgoing message against current module permissions, session version and device access; root-only activation channels remain root-only. Revocation blocks delivery on existing sockets. Browser clients obtain tickets before STOMP CONNECT; local preview remains polling by default. Admin proxy debug logs no longer print response bodies or session-token metadata.

Twelve operational modules now use `/api/v1/operations`: SIM cards, job cards, downtime, faults, parts, fuel-card entries, calibration, camera data plans, storage policies, maintenance defaults, Fuel alert rules and Video alert rules. Records support server search/sort/paging, validated create/edit/delete and atomic CSV import. Server authorization permits writes only to root, admin and fleet-manager roles, and checks linked-device access. Calibration writes the existing ingestion calibration curve. Storage policies and data plans are recorded configuration; automated retention enforcement and provider usage synchronization remain unfinished.

Fuel rules save one policy per device with low-fuel/drop thresholds, enable switches and a whole-minute drop window. Both fuel-sensor ingestion and tracker fuel evaluation use the policy. Video rules save enabled/minimum-severity settings; camera alerts are filtered before persistence/broadcast, without deleting received footage. Policies apply within 15 seconds. Deleting a policy restores existing defaults. Duplicate rules, cross-tenant writes and relinking an existing policy are rejected.

Role profiles and Modules now use root-only operational record schemas and separate admin-session proxies. Profiles define a built-in base role plus None/Read/Write access per module. Viewer/driver profiles cannot grant writes; dependent fleet modules require read access to the shared Control Center directory. Account module policies override profiles. User assignment updates the base role and ends existing sessions; root roles cannot be replaced through profiles. Assigned profiles cannot be deleted. Login, sidebar, page access, search, widgets and write controls use effective permissions, with server checks on every authenticated API request.

JWT authentication now verifies current database roles, enabled state and session version instead of trusting stale role claims alone. Disabling an account increments its session version, so re-enabling it does not revive old tokens. Suspended/inactive/disabled organisations lose module access while retaining session information and Support. AI tools, insight categories and cache identities respect module permissions. Root Reset hub supports password- and target-email-confirmed session revocation and clearing selected-user saved preference records, with audit entries. It does not claim to clear another browser's local display preferences. Migration V31 adds access-profile/session-version fields and indexes; it has not been executed against PostgreSQL.

Maintenance Alerts now lists open work orders due by the selected period end, including earlier overdue work, and excludes completed/cancelled work. Today, Next 7 days, Next 30 days and Custom periods are available. Attention labels distinguish overdue, due today and upcoming work, with days remaining and recorded cost. Work-order reads/writes enforce organisation or personal ownership; viewers cannot mutate them. Completion sets a timestamp and reopening clears it. Maintenance API responses use explicit DTOs. Committed operational/maintenance writes invalidate cached reports immediately.

Four fuel workspaces now use `/api/v1/reports`: Refuels, Drains & theft, Consumption and Fuel reports. Six report variants include vehicle/driver consumption, range forecast and trip fuel efficiency. They provide tenant/date scope, custom periods up to 31 days, search/sort/status filters, full matching CSV/XLSX exports and browser Print/PDF. Fuel changes use a 5 L or 5% tank threshold; suspected drains require review. Missing tank readings leave complete vehicle totals unavailable. Driver efficiency pairs fuel and distance from the same trips. Reports cache scoped calculations for 30 seconds.

Video Analytics, Video Reports, Maintenance Reports and SMS Reports now share that report workspace. Video reports use received camera events and distinguish clips received from pending clips. Maintenance reports select work orders by creation time. SMS reports select device-linked messages only for accessible IMEIs; unlinked platform messages appear only for root with All tenants. Message bodies and provider responses are omitted from these reports. These are record-derived reports; no provider telemetry or delivery outcomes are invented.

## Running the local browser preview

Start `tracpro-backend/start-local-preview.ps1` and `smarttrack-web/scripts/start-local-preview.ps1` in separate PowerShell terminals. Open `http://localhost:3000/login`; the backend listens on `127.0.0.1:8089`. Successful sign-in defaults to Dashboard.

The preview profile uses `tracpro-backend/data/signature-preview` (ignored by Git), Hibernate schema update and no Flyway migrations. It disables hardware listeners and external SMS/email/AI/media integrations. A Redis client points only at `127.0.0.1:6380`; no Redis service is bundled, so Redis-dependent activation/cache functions are unavailable. The frontend uses polling in this profile. Production configuration and environment files are unchanged.

The profile seeds `admin@smarttracker.local` with password `Preview123!` (overridable with `SMARTTRACKER_PREVIEW_PASSWORD`). The older development account entered during preview has also been created in this local database. Both are local preview accounts, and fleet data starts empty.

The real-login smoke check exposed an existing driver query passing a string to an enum parameter. The repository and controller now use the `DRIVER` enum. Root users in the client workspace fetch tenant choices using their client session through `/api/organisations`, without requiring a separate admin-console cookie.
